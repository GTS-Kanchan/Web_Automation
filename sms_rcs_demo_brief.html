04 — SINGLE LOGIN

One login per run, not one per test

Every test authenticates, but the suite only ever drives the real login UI once per pytest run — regardless of how many tests or parallel workers are involved. Everyone else reuses a saved session.
first worker claims an exclusive, atomic lock file before anyone else can
→
real UI login logs in through the actual app once, using VALID_EMAIL / VALID_PASSWORD
→
storage_state.json the authenticated session (cookies + local storage) is saved to disk
→
every other test opens its browser context pre-authenticated from that file — no login screen, ever
Why it matters for the demo: you can run the whole SMS or RCS suite, or split it across several parallel workers, and the login form only appears once at the very start — not once per test class.
  • whereImplemented in utils/auth_state.py, wired into every test through the logged_in_page and module_logged_in_page fixtures in conftest.py.
  • race-safeThe lock is acquired with an atomic file-create (O_CREAT | O_EXCL), so if several pytest-xdist workers start at once, exactly one of them performs the real login and the rest wait for its result.
  • no login stormsIf the real login fails, a failure marker stops every other worker from immediately retrying it and hammering the login page — retries are gated behind a cooldown (TTL) instead.
  • self-healingA stale lock or stale failure marker (left behind by a crashed run) expires automatically, so the next run isn't permanently blocked by a previous bad state.
  • configSession file location is AUTH_STATE_PATH (default reports/.auth/state.json); credentials come from VALID_EMAIL / VALID_PASSWORD in .env — not shown here.
